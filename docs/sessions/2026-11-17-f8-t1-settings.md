### Technical Details
- **Settings** (`SettingsFeature`, `SettingsFlow`): the shared `SettingsContent`. Permissions, detection (sensitivity, sleep talking, Debug raw audio), appearance, profile and briefing switch, storage limits (lowering asks first), Apple Health sync (Health brands), delete all, version, rating once a brand has an App Store id, Debug test cleanup and sample nights. No Watch section: no brand has a Watch app.
- **Profile editor**: the shared `ProfileEditorContent` as a sheet; stored as a JSON file (`ProfileStore`), saved on Save and on close as SleepGuard does.
- **Start delay**: the prestart's delay row; `RecordingFlow` shows the countdown with the capture warmed up (`AudioCapturePort.warmUp`), a notification at the start time, Cancel back to the prestart, Start now or zero to the night on the warm capture.
- **Storage limits** (`EnforceStorageLimits`): SleepCore's `StoragePlan` picks the nights; their clips and raw files go, the nights stay. Also removes files no saved or checkpointed night refers to (a crash's leftover clip). Runs at launch, after each save, after lowering a limit.
- **Delete all** (`DeleteAllData`): nights, every file in the clips folder, the checkpoint. Profile and settings stay.
- **Apple Health** (ADR 0006): `BrandConfiguration.health` is a port the brand builds (`SleepHealth.makeHealthAccess()`) or `nil` (Lite); `CommitSession` writes the night when sync is on, with SleepGuard's metadata. Health brands get the usage texts in Info.plist.
- **Raw recording** (Debug, when on): the capture writes `rawaudio_<id>.caf`, `RecordingSession` writes `rawlog_<id>.jsonl` in SleepCore's `RawLog` format, in batches.
- **Preferences**: `PreferencesStore` over UserDefaults, one key per setting (SleepGuard's names). `RecordingComposer` uses them instead of hard-coded defaults.
